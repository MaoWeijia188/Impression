# 印象问答 · 开发任务拆分

关联：`01-产品需求文档.md` ~ `04-API接口清单.md`

**目标：两周内做出可以让朋友真实使用的第一版，而不是两周内学会所有技术。**

> 说明：下表的「预估」是给人天量级的概念参考，默认每天有稳定投入且会用 AI 辅助编码。如果某个技术是从零学起，请自行翻倍。

**⚠️ 已知坑**

- Boot 4 的 starter 做了模块化拆分，创建后**先确认 Web starter 的实际 artifactId**（Initializr 生成的就是对的，不要凭记忆手写）。
- ORM 用 MyBatis-Plus，必须加 `com.baomidou:mybatis-plus-spring-boot4-starter`（3.5.13+）。**用成 `mybatis-plus-spring-boot3-starter` 会启动报错**。加了 MyBatis-Plus 后**不要再加** `mybatis-spring-boot-starter`。
- `pom.xml` 的 `groupId` 别留默认的 `org.example`，改成自己的（如 `com.maoweijia.impression`）。

### M4 · 公开接口（核心）

| 编号 | 任务 | 产出 | 验收标准 |
|---|---|---|---|
| T-18 | P-01 获取问卷基本信息 | `QuestionnaireController` | 分享码无效返回 40402 |
| T-19 | P-02 获取题目与选项 | 同上 | **不泄露任何统计字段** |
| T-20 | P-03 提交回答 —— **事务 + 校验** | `SubmissionService` | 伪造 optionId 被拒；必答缺失被拒 |
| T-21 | P-03 —— **幂等** | `submit_token` 唯一索引 + 捕获冲突 | 相同 token 提交两次 → 只落 1 条，第二次返回 `duplicated:true` |
| T-22 | P-03 —— **问卷关闭校验** | 校验与写入同事务 | 关闭后提交返回 40901 |
| T-23 | 开放题长度与 XSS 过滤 | 文本清洗 | 超过 200 字被拒；`<script>` 被转义 |

**必须自己动手验证的三件事**

1. 用 Postman 改一个别的问卷的 `questionId` 提交 → 是否被拒？
2. 连续点两次提交 → 数据库里有几条？
3. 先把问卷关掉，再提交 → 返回什么？

**对应面试知识点**（这是整个项目最值钱的部分）：`@Transactional` 的传播行为与失效场景、唯一索引做幂等、防越权的参数归属校验、输入校验与输出转义。

## 2. 面试可讲点映射（写简历 / 自我介绍时直接可用）

| 你做过的事 | 面试能讲什么 |
|---|---|
| P-03 提交接口 | 用唯一索引 + 捕获冲突实现**幂等**，而不是靠前端防抖；讲清楚为什么 |
| `SubmissionService` 的事务 | `@Transactional` 的边界为什么这么划；校验与写入为什么必须同事务 |
| 参数归属校验 | 防御 **IDOR 越权**：不能只验 id 存在，必须验「这个 id 属于当前用户」 |
| `answer_option.question_id` 冗余 | 一次**有意识的、代价可控的反范式**，以及如何保证一致性 |
| 统计 SQL | `LEFT JOIN` 让 0 票选项不丢；索引如何覆盖高频统计查询 |
| 限流 | 固定窗口 vs 滑动窗口的取舍 |
| 样本量门槛 | 产品层面的**统计严谨性**：样本不足时不下结论 |
| 部署 | Nginx history 路由坑、同源部署免跨域、备案的现实约束 |

## 5. 每个里程碑结束时的自检问题

1. 这个功能**能被别人用**吗？（不是「代码写完了」）
2. 我能**不看代码**说清它的数据流吗？（请求 → Controller → Service → Mapper → 表）
3. 输入脏数据会发生什么？我知道吗？
4. 如果明天要加一种题型，我需要改哪些文件？
5. 这段代码我能**自己重写一遍**吗？
