## 1. 项目背景与目标

### 1.1 背景

把「印象问答」的专属链接发到朋友圈，朋友回答一组关于我的问题，系统汇总后生成一份「朋友眼中的我」的印象结果与可分享的结果卡片。

这个想法同时满足两个目的：

- **产品目的**：做一个真的有人愿意用的轻量社交互动产品，不是玩具 demo。
- **个人目的**：作为 Java 后端 + AI 应用方向的第一个完整 Web 项目，覆盖「需求 → 设计 → 开发 → 部署 → 数据驱动迭代」全链路。

### 1.2 项目目标（可验证，不是口号）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 跑通完整产品链路 | 链接可发朋友圈，朋友能在手机上完成答题并看到结果 |
| G2 | 拿到真实用户数据 | ≥ 20 位不同朋友完成提交 |
| G3 | 验证传播假设 | ≥ 3 位朋友点击「创建我自己的问卷」并完成创建 |
| G4 | 形成可写进简历的技术产出 | 有一个部署上线、有真实数据、迭代过至少 1 次的线上项目 |
| G5 | 沉淀可讲的面试素材 | 能讲清楚：为什么这样设计表、如何处理重复提交、如何做权限校验、统计 SQL 怎么优化 |

### 1.3 成功标准（第一版上线后判定）

- **必须**：G1 达成。技术验收清单见第 6 章。
- **期望**：G2 达成，且完成率（提交数 ÷ 打开答题页数）≥ 60%。
- **惊喜**：G3 达成。

> 假设不成立怎么办：如果上线两周后提交数 < 5，问题大概率在「传播路径」或「答题动机」，而不是代码。届时优先改文案与分享卡片，而不是加功能。

## 2. 用户与场景

### 2.1 角色定义

| 角色 | 说明 | 第一版是否需要账号 |
|---|---|---|
| **创建者 Creator** | 创建问卷、分享链接、查看汇总结果的人（第一版就是我自己） | 否，用「创建者凭证」代替登录 |
| **答题者 Respondent** | 通过链接进入、回答问题的朋友 | 否，完全免登录 |
| **访客 Visitor** | 只打开链接不答题 | 否 |

### 2.2 核心使用场景

**场景 A（主场景）**
我在朋友圈发一条：「我做了一个小测试，想知道你眼中的我是什么样的人，一分钟，匿名，帮我填一下 👉 链接」→ 朋友点开 → 看到 8–10 道题 → 1–2 分钟答完 → 提交 → 看到「已收到」和一个「也创建一个我自己的」入口。

**场景 B（查看结果）**
我打开自己的管理链接，看到：已收到 18 份回答、每道题的选项分布、朋友写的开放题原文、以及一张可保存的结果卡片。

**场景 C（传播）**
朋友 B 答完后点了「创建我自己的问卷」→ 拿到自己的链接 → 发给他的朋友 → 循环。

### 2.3 用户故事（User Story）

| 编号 | 角色 | 用户故事 | 优先级 |
|---|---|---|---|
| US-01 | 创建者 | 我希望不用注册就能创建一份问卷，这样我可以马上发给朋友 | 必须 |
| US-02 | 创建者 | 我希望拿到一个专属链接，这样我可以直接发朋友圈 | 必须 |
| US-03 | 答题者 | 我希望点开链接就能直接答题，不用登录，这样我不会中途放弃 | 必须 |
| US-04 | 答题者 | 我希望知道大概要花多久、一共几道题，这样我愿意开始 | 必须 |
| US-05 | 答题者 | 我希望提交后立刻看到明确反馈，这样我知道成功了 | 必须 |
| US-06 | 答题者 | 我希望我的回答是匿名的，这样我敢说真话 | 必须 |
| US-07 | 创建者 | 我希望看到每道题的回答分布，这样我知道大家怎么看我 | 必须 |
| US-08 | 创建者 | 我希望看到开放题原文，这样我能读到真实的评价 | 必须 |
| US-09 | 创建者 | 我希望拿到一张好看的结果卡片，这样我能分享 / 保存 | 必须 |
| US-10 | 创建者 | 我希望可以关闭问卷，这样我不想再收回答时能停止 | 必须 |
| US-11 | 创建者 | 我希望可以删除某条不当回答，这样我能保护自己 | 应该 |
| US-12 | 答题者 | 我希望答完后也能创建自己的问卷 | 应该 |
| US-13 | 创建者 | 我希望有一份 AI 写的综合印象分析 | 后续（v1.2） |
| US-14 | 创建者 | 我希望 AI 根据主题帮我出题 | 后续（v1.2） |

## 3. 功能范围

### 3.1 MVP（第一版必做）

| 模块 | 功能点 | 说明 |
|---|---|---|
| 问卷 | 创建问卷 | 免注册；创建后返回「创建者凭证」+「分享码」 |
| 问卷 | 编辑基本信息 | 标题、描述 |
| 问卷 | 开启 / 关闭 | 关闭后拒绝新提交 |
| 问卷 | 删除问卷 | 连带删除题目与回答 |
| 题目 | 预置题目 | 第一版**只用一套预置题库**，不做可视化出题器 |
| 题目 | 支持三种题型 | 单选 / 多选 / 开放题 |
| 答题 | 答题页 | 移动优先、一屏一题或一屏多题、必填校验 |
| 答题 | 提交 | 防重复提交；返回提交凭证 |
| 结果 | 答题者反馈页 | 提交成功 + 传播入口 |
| 结果 | 统计 | 各题选项分布、开放题原文列表 |
| 结果 | 结果卡片 | 固定模板，前端 canvas 生成可保存的图片 |
| 管理 | 管理页 | 查看回答数量与内容、逐条删除回答 |
| 基础 | 分享链接 | 不可预测的分享码，`/u/{shareCode}` |

### 3.2 明确不做（Out of Scope，第一版）

把「不做」写清楚，和「做」一样重要：

- ❌ 账号体系（注册 / 登录 / 找回密码 / 个人中心）
- ❌ 可视化题目编辑器（自由增删改题目、拖拽排序）
- ❌ 好友关系、评论、点赞、排行榜
- ❌ 匿名留言墙
- ❌ AI 相关的一切功能（印象分析 / 智能出题 / 文案生成）
- ❌ 数据埋点 SDK、A/B 实验框架
- ❌ Redis / 消息队列 / 微服务拆分
- ❌ 微信 JS-SDK 自定义分享卡片（见 3.3 的现实约束）

> **决策原则**：第一版的目标是「两周内做出能让朋友真实使用的版本」，不是「两周内学会所有技术」。任何会推迟上线的功能都砍掉。

### 3.3 已知的现实约束（务必先知道，别到上线才发现）

| 约束 | 影响 | 第一版对策 |
|---|---|---|
| 微信内打开非微信域名外链会提示「非官方网页」 | 影响观感，但不阻断访问 | 接受；域名备案后观感更好 |
| 朋友圈 / 微信内**自定义分享卡片**（标题、缩略图）需要微信 JS-SDK，而 JS-SDK 需要**认证的公众号** | 无法做「一键分享带图卡片」 | **降级方案**：结果卡片生成图片 → 用户手动保存 → 自己发朋友圈 |
| 大陆服务器需要 ICP 备案 | 影响上线时间 | 先用中国香港 / 海外节点 + 域名自测；正式运营前再备案 |

### 3.4 迭代路线

| 版本 | 内容 | 触发条件 |
|---|---|---|
| v1.0 | 上面 3.1 的 MVP | — |
| v1.1 | 题目自由编辑、结果卡片多模板、访问来源统计 | v1.0 有 ≥ 20 份提交 |
| v1.2 | AI 综合印象分析（只在样本充足时生成，且必须标注依据） | v1.1 稳定运行 |
| v2.0 | AI 出题、多问卷对比、时间维度趋势 | 有持续使用的真实用户 |

## 4. 产品规则（关键决策，写死）

### 4.1 题目设计

题目分四个维度，混合三种题型：

| 维度 | 想了解什么 | 示例 |
|---|---|---|
| 第一印象 | 刚认识时的感受 | 你第一次见我时，觉得我是什么样的人？ |
| 相处体验 | 日常相处中的感受 | 我更像倾听者还是表达者？ |
| 性格特征 | 朋友眼中的个性 | 你觉得我最大的优点是什么？ |
| 关系认知 | 对彼此关系的感受 | 用一种场景形容我们之间的关系，你会选？ |

**题量与配比（v1.0 基线）**

- 总题量 **8–10 题**，目标完成时间 **1–2 分钟**
- 单选 4–5 题、多选 2–3 题、开放题 **1–2 题（必须可跳过）**
- 多选题**最多选 3 项**，不要把 12 个选项让人排序

> 这是一个**待验证假设**，不是已证明的最优题量。上线后按实际完成率与跳题率调整。

### 4.2 结果生成规则（最重要的一节）

结果分三层展示：

**第一层：直观结果**（来自选择题统计）

- 最突出的特质（被选次数最多的选项）
- 最常见的第一印象
- 最明显的反差（同一维度上分歧最大的两项）

**第二层：具体反馈**（开放题原文）

- 按提交顺序或随机展示，**不附带任何身份信息**

**第三层：综合画像**（v1.2 才由 AI 生成，v1.0 用规则文本模板）

**硬性约束（必须实现，这是产品可信度的底线）：**

| 规则 | 说明 |
|---|---|
| 样本量门槛 | 提交数 < 3 时，**只显示「目前收到 N 份回答」**，不生成倾向性结论 |
| 不把个例说成共识 | 只有 1 人提到某特质时，必须表述为「有 1 位朋友提到」，不能说「大家都觉得」 |
| 有分歧就如实呈现 | 回答明显分裂时，展示分歧本身，而不是强行总结出一个性格结论 |
| 不做人格诊断 | 不出现「你本质上是一个…」这类确定性人格断言 |

### 4.3 匿名与隐私规则

| 规则 | 具体做法 |
|---|---|
| 答题端免登录 | 打开链接直接答 |
| 不采集姓名 | 第一版**完全不采集**任何身份信息 |
| 不采集精确 IP | 如需风控去重，只存**哈希后的 IP**，不存明文 |
| 开放题限长 | 单题上限 200 字，前端 + 后端双重校验 |
| 可跳过 | 开放题允许不填 |
| 可删除 | 创建者可逐条删除回答；可关闭问卷 |
| 明确告知 | 答题页开始前用一行字说明：回答将展示给创建者，且不会记录你的身份 |

> ⚠️ **不要向用户承诺「绝对匿名」**。只要系统记录了 IP 哈希、时间戳、设备信息，就不是绝对匿名。文案要写「不记录你的身份信息」，而不是「完全无法追踪」。

### 4.4 传播机制

```
A 创建问卷 → A 分享给 B/C/D → B/C/D 完成回答
        → B 感兴趣 → B 创建自己的问卷 → B 分享给他的朋友
```

结果页必须有一个**轻量、不打扰**的入口：

> 也想知道朋友眼中的自己？→ 创建我的印象问卷

> 入口只是「提供了可能性」，不保证带来增长。真正的增长取决于朋友的回答体验是否足够好。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| **性能** | 答题页首屏 ≤ 2s（4G 网络）；提交接口 P95 ≤ 500ms；统计接口在 500 份提交内 P95 ≤ 1s |
| **兼容性** | 移动优先；iOS Safari / 微信内置浏览器 / Android Chrome 正常；最小宽度 320px |
| **可用性** | 提交后数据必须落库（刷新不丢）；重复点击提交不生成两份答卷 |
| **安全** | 分享码不可预测（≥ 8 位随机）；管理接口必须校验创建者凭证；所有入参后端校验；开放题做 XSS 转义 |
| **可维护性** | 分层清晰（Controller / Service / Mapper）；配置与代码分离；数据库变更用 SQL 脚本管理 |
| **可观测** | 记录关键日志（创建、提交、异常）；不打印敏感信息 |

## 6. 验收标准（发出朋友圈之前逐条打勾）

1. ☐ 手机浏览器能正常打开，布局不错乱
2. ☐ 题目与选项显示正确，三种题型都能作答
3. ☐ 必填校验生效，未答完无法提交
4. ☐ 提交成功后有明确反馈
5. ☐ 刷新页面后，已提交的数据仍然存在
6. ☐ 统计结果与实际回答一致（人工核对一遍）
7. ☐ 不同问卷之间的数据不串（用两个问卷交叉测试）
8. ☐ 重复点击提交只生成一份答卷
9. ☐ 问卷关闭后，提交接口返回明确错误
10. ☐ 直接用别人的管理链接访问，会被拒绝
11. ☐ 结果卡片能正常生成并保存到手机
12. ☐ 隐私说明与删除机制已经具备

## 7. 假设与风险

| 编号 | 假设 / 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 假设 8–10 题、1–2 分钟是最优题量 | 完成率可能偏低 | 上线后看跳题率与完成率调整 |
| R2 | 假设朋友愿意在朋友圈点开一个陌生链接 | 打不开量 | 优化封面文案，降低首屏认知成本 |
| R3 | 开放题可能收到攻击性 / 不当内容 | 伤害创建者 | 限长 + 逐条删除 + 可关闭问卷 |
| R4 | 分享码被猜到，他人可访问 | 隐私泄露 | 使用足够长的随机码 + 权限校验 |
| R5 | 大陆部署需备案，拉长上线周期 | 上线延迟 | 先用海外 / 香港节点自测 |
| R6 | 技术栈陌生导致项目烂尾 | 无法上线 | 严格执行「先跑通再做深」，允许第一版很丑 |

## 8. 技术选型基线（v1.0）

| 层 | 选型 | 备注 |
|---|---|---|
| 语言 | **Java 25（LTS）** | Spring Boot 4.1 支持 Java 17–26；25 是当前 LTS |
| 后端 | **Spring Boot 4.1.x** | ⚠️ 3.5.x 已于 2026-06-30 结束开源维护，新项目不要再用 3.x |
| 构建 | **Maven + Maven Wrapper（`mvnw`）** | 用 wrapper 就不必全局安装 Maven |
| ORM | **MyBatis-Plus** | ⚠️ Boot 4 必须用 `mybatis-plus-spring-boot4-starter`（3.5.13+），用成 boot3 starter 会启动报错 |
| 数据库 | **MySQL 8.4**（本机已安装） | InnoDB + utf8mb4 |
| 前端 | **Vue 3 + Vite + Vue Router + Axios** | 移动优先 |
| 样式 | 手写 CSS（CSS 变量做主题） | 不引组件库，减少依赖、方便控体积 |
| 部署 | Nginx（托管静态文件）+ Spring Boot jar | 备案与 HTTPS 见 3.3 |

> 版本号请在真正创建项目时以 Spring Initializr（start.spring.io）生成的为准，本文档只固定「选型方向」和「已知坑」。
