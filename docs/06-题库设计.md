## 1. 统一后的题型模型

**只有一种题型**，每题由三件事描述：

| 能力 | 说明 | 可配置 |
|---|---|---|
| **多选** | 可以勾选任意多个预设选项 | `maxSelect`：0 = 不限；填数字则封顶 |
| **自定义** | 除了勾选项，还能自己写一段文字 | `maxLength`：默认 200 字 |
| **跳过** | 任何一题都可以不答，直接下一题 | 全局放开；另有「至少答 N 题」的提交下限 |

**没有预设选项的题，就是纯自由填写题**（`options: []`）——原本的 4 道"开放题"用这个表达，不需要单独的类型。

### 答案结构（前后端一致）

```jsonc
{
  "q1": { "keys": ["A", "C"], "custom": "" },              // 只勾了选项
  "q2": { "keys": [],        "custom": "第一印象是很安静" },  // 只自己写了
  "q3": { "keys": ["A"],     "custom": "补充一句……" },      // 两者都有
  "q4": { "keys": [],        "custom": "" }                // 跳过（空答案，不入库）
}
```

`keys` 和 `custom` **可以同时存在**——这是与 v1.0 最大的结构差异。

### 题目配置

```jsonc
{
  "id": "q1",
  "dimension": "第一印象",            // 仅用于前端分组展示与统计归类
  "title": "第一次接触我时，我在你眼里有哪些标签？",
  "options": [                       // 留空数组 [] = 纯自由填写题
    { "key": "A", "text": "靠谱" }
  ],
  "maxSelect": 0,                    // 0 = 不限
  "maxLength": 200,                  // 自定义答案字数上限
  "customPlaceholder": "上面都不太准？用自己的话描述一下第一印象…"
}
```

## 3. 必须付的代价（这一版最重要的部分）

把题型全部放开，收益是**不丢信息**（朋友不会被选项框住），代价有三个，必须提前认下来：

### 3.1 选择题的"分布"不再等于"结论"

- 单选变多选后，各选项的占比**加起来会超过 100%**，不能再解读为"多数人选了 X"。
- **正确读法**：`选择该选项的人数 ÷ 回答本题的人数`。分母是**回答本题的人数**，不是总提交数——因为题目可以跳过，这两个数不相等。
- 「最突出的特质」这类结论仍然成立，但要表述为"被提到最多的"，而不是"最多人选择的"。

### 3.2 自定义答案无法自动聚合

这是最实际的成本。自定义答案会产生大量同义不同写法：

```
"靠谱" / "很靠谱" / "挺靠谱的一个人" / "说到做到"
```

这四条在数据上是四行独立文本，**统计上会被算成 4 个不同的东西**。所以：

- 有预设选项的题，自定义答案**不要**合并进选项分布图，应单列一块「另外有 N 条自己写的」。
- 纯自由题（O1–O4）天然只能按原文展示，本来就无法量化。
- 想做归类（把"很靠谱"归到"靠谱"），**这是 v1.2 里 AI 的第一个真实落地点**——比"AI 写印象分析"更具体、更好验收：输入一批自由文本，输出归并后的标签 + 计数。

### 3.3 数据会变稀

全部可跳过 + 全部可多选，意味着：

- 每题的**回答人数**不同，样本量要逐题算，不能只报一个总数。
- 理论上一份答卷可能只有 1 道题有内容。原型的对策是设了**提交下限：至少答 1 题**（`CONFIG.minRequiredAnswers`）。若想更严，改成 3 或 5。
- PRD §4.2「样本 < 3 不下结论」的规则要**按题判断**，而不是按问卷判断。

### 3.4 一个仍然有效的旧建议

`4-1 / 4-2 / 4-3` 三道都在问"我们算什么关系"，角度差异小于措辞差异。**建议砍掉 `4-3`**（总题量回 10 题、维度分布 2/2/3/3）。这条与题型统一无关，是原有的结构问题。

## 4. 与数据库的映射

| 前端字段 | 数据库落点 |
|---|---|
| `keys[]` | `answer_option` 表，**每个选中项一行** |
| `custom` | `answer.text_content` |
| 整题的答案 | `answer` 表一行（`submission_id` + `question_id` 唯一） |
| 跳过（`keys` 与 `custom` 都为空） | **不插入 `answer` 行** |

⚠️ 需要注意：v1.0 的 `answer.text_content` 注释写的是「开放题文本；选择题为 NULL」。**这条语义已经失效**——现在任何题都可能同时有选项和文本。详见 `07-题型统一-影响评估.md`。

## 5. 想改题库怎么做

编辑 `prototype/index.html` 顶部的 `QUESTIONS` 数组即可，**逻辑无需改动**：

- 想加一道有选项的题 → 复制一个对象，填 `options`
- 想加一道纯自由题 → `options: []`
- 想限制某项最多选 3 个 → `maxSelect: 3`
- 想强制必答 → 全局把 `CONFIG.minRequiredAnswers` 调高（当前是"至少 1 题"）

数组顺序 = 出题顺序。
