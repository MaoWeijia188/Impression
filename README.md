# Impression · 印象问答

> 一个帮你了解「朋友眼中的自己是什么样的人」的轻量互动产品。

把专属链接分享到朋友圈，朋友花 1～2 分钟回答一组关于你的问题，系统汇总后生成一份印象结果与可分享的结果卡片。

本项目同时作为 **Java 后端 + AI 应用方向** 的个人实践项目，目标是在真实使用中跑通「产品设计 → 前后端开发 → 数据库设计 → 部署上线 → 数据驱动迭代」的完整链路。

## 🗄 数据库脚本

在 MySQL Workbench 里**按顺序**执行（新建 Query Tab → **全选粘贴 → 整体执行**。不要只选中单条语句执行，脚本用会话变量 `@qid` 串联）：

| 顺序 | 脚本 | 作用 | 可重复执行 |
|---|---|---|---|
| 1 | [`sql/V1__init_schema.sql`](sql/V1__init_schema.sql) | **清空并重建** `impression` 库，创建 6 张表 | ⚠️ 是，但会清空已有数据 |
| 2 | [`sql/V2__seed_questions.sql`](sql/V2__seed_questions.sql) | 写入示例问卷 + 11 道题 + 40 个预设选项 | 否（重来请先重跑 V1） |

> V1 的第一条语句是 `DROP DATABASE IF EXISTS impression` —— 它只影响 `impression` 这个库，不会碰你机器上其它数据库。
> **一旦库里有了真实回答，就不要再跑 V1**，改为写增量 `ALTER` 脚本（约定见 `docs/03-数据库设计.md` §8）。
>
> V2 执行完会 SELECT 出 `share_code` 与 `owner_token` 两个值，分别用于答题链接和管理接口，请抄下来。

## 一、产品定位

| 项 | 说明 |
|---|---|
| 目标用户 | 想让朋友评价自己的普通用户（第一版由本人自用并分享到朋友圈） |
| 核心价值 | 把「朋友对你的真实印象」变成一份好看、可分享、有情绪共鸣的结果 |
| 传播方式 | 专属链接 + 结果卡片 + 「也创建一个我自己的」入口 |
| 不做什么 | 不做账号体系、不做好友关系链、不做排行榜（第一版全部暂缓） |

### 用户流程

```
朋友圈分享链接 → 首页（了解玩法）→ 回答 11 道题
→ 提交 → 生成印象结果 → 查看结果 + 结果卡片 → 分享 / 创建自己的问卷
```

### 结果页三个层次

1. **直观结果** —— 选项统计（最突出的特质、最常见的第一印象）
2. **具体反馈** —— 开放题原文（真实反馈比系统生成的漂亮话更有价值）
3. **综合画像** —— 基于实际回答的归纳；**样本不足时必须如实说明，不能把单份回答说成共识**

## 三、数据库核心实体

```
questionnaire 问卷
  ├── question 题目 ── question_option 预设选项
  └── submission 一次答题
        └── answer 单题答案 ── answer_option 被选中的选项
                └──（自由/自定义答案文本存在 answer.text_content）
```

六张表，DDL 见 `sql/V1__init_schema.sql`。**题型已统一**：每题都可以多选、都可以自定义答案、都可以跳过，所以 `question.type` 只区分「有预设选项 / 纯自由填写」，不再有单选/多选/开放之分。

- 规范建模，**不要把整份问卷的回答塞进单个字段**
- 覆盖的练习点：一对多关系、主键/外键与级联删除、索引设计、分页查询、聚合统计、事务与幂等
- 「跳过」用**不写入 `answer` 行**表达，不引入冗余状态字段

## 六、注意事项

- **隐私**：答题端免登录；默认不收集姓名；开放题限长并支持跳过；提供删除回答、关闭问卷的能力
- **安全**：随机不可预测的分享标识 + 创建者权限校验；防止重复提交；问卷关闭后拒绝提交
- **合规**：面向中国大陆用户正式运营前，需核实域名、服务器地域与备案要求
